### what I'm actually building

**Unsur Tulung** is an odd-job and multi-service platform for students around campus — errands, pickup and delivery, print and binding, room cleaning, admin help, all ordered through WhatsApp. Two-tier pricing so students and locals pay differently. A small team runs it with me.

The whole site is a single HTML file — Tailwind CSS and Alpine.js, no build step, no framework weight — with a live order form, a receipt-style preview, and a WhatsApp deep link that fires the order straight through. Real users. Real names and phone numbers moving through it daily. Which is exactly why the rest of this document isn't a buzzword list.

### the triad I actually build against

Most people learn CIA to pass an exam. I use it as a checklist — for Unsur Tulung, for my own code, for whatever I bother finishing.

**Confidentiality**
Real names, numbers, and addresses move through Unsur Tulung every day. Nothing gets logged that doesn't need to exist. Nothing gets shared past whoever actually needs to see it. Not a security elective — just how I was already building it before I had a name for the principle.

**Integrity**
Data should say what actually happened, unaltered. Same standard for a database row as for this README — I'd rather write "still learning" and mean it than pad a bio with words that fall apart under one follow-up question.

**Availability**
A service you can't reach when you need it might as well not exist. Unsur Tulung runs on WhatsApp on purpose — no app to install, no login to forget, nothing standing between a student and getting something done. Same principle, whatever scale I've actually got.
